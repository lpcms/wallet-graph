# Wallet Graph

Визуализация связей между Ethereum-кошельками и держателями токенов по данным Etherscan:
граф переводов, кластеризация адресов одного владельца, капитализация группы кошелька
и прогноз направления цены нейросетью.

## Структура

```
api/            REST API на NestJS: загрузка данных Etherscan, граф, кластеры, прогноз
  src/
    main.ts                 точка входа
    app.module.ts
    config.ts               настройки из .env
    constants/              известные адреса бирж и сервисов
    controllers/            HTTP-эндпоинты, сборка графа, 2-й хоп, капитализация
    services/               Etherscan, кластеризация, аналитика, граф, модель
    lib/                    Union-Find
  test/                     тесты (Vitest)
  scripts/                  postinstall-фикс tfjs-node для Windows
graph/          фронтенд на Next.js + Sigma.js
  app/
    page.tsx                главная страница
    components/WalletGraph.tsx
    lib/                    адрес API, форматирование сумм
    types/
  tests/                    тесты (Vitest)
```

## Требования

- Node.js 24
- Ключ [Etherscan API](https://etherscan.io/myapikey) (бесплатного достаточно, лимит — 3 запроса/с)

## Запуск

```bash
# API — http://localhost:3001
cd api
cp .env.example .env        # вписать ETHERSCAN_API_KEY
npm install
npm start

# Фронтенд — http://localhost:3000
cd graph
cp .env.example .env.local  # если API не на localhost:3001
npm install
npm run dev
```

## API

| Метод | Описание |
|---|---|
| `GET /health` | состояние и текущие настройки |
| `GET /graph/wallet/:address?hops=15&width=10` | граф кошелька: вся история + хопы (1–15, по `width` адресов на хоп, 5–50), капитализация группы |
| `GET /graph/wallet/:address/stream?hops=&width=` | то же с прогрессом по хопам через SSE |
| `GET /graph/token/:address` | граф держателей ERC-20 токена |
| `GET /graph/token/:address/full` | полная история токена, прогресс через SSE |
| `GET /predict/:symbol` | прогноз направления и фазы рынка по свечам Binance (кэш 30 мин) |
| `GET /predict/:symbol/retrain` | переобучить модель принудительно |

**Капитализация группы** — сумма ETH-балансов, из которой исключены биржи, смарт-контракты
и кошельки с 10 000+ транзакций (горячие кошельки бирж, маркет-мейкеры, боты):

- `nearUsd` — ближнее окружение: адреса не дальше 2 хопов от кошелька;
- `allUsd` — всё окружение: все адреса графа (на дальних хопах попадаются крупные холодные
  кошельки, поэтому эта сумма может быть в десятки раз больше);
- `clusterUsd` — кластер кошелька (адреса, которые эвристики считают одним владельцем).

Балансы токенов не учитываются.

**Хопы.** Граф кошелька раскрывается «по деньгам»: на каждом следующем хопе загружаются
транзакции `width` самых крупных по объёму ETH новых контрагентов адресов предыдущего хопа.
Биржи, контракты и адреса с очень частыми транзакциями (боты, горячие кошельки) дальше
не раскрываются, поэтому цепочки обрываются, когда деньги доходят до биржи. У каждого адреса
два номера: кратчайший путь (наименьшее число переводов от кошелька) и шаг цепочки (на каком
шаге раскрытия адрес впервые встретился); оба есть в режиме цвета «Хоп». Время растёт с числом
запросов к Etherscan (3 в секунду): 15 × 10 — до ~3,5 мин, 15 × 50 — до ~7,5 мин.

**Категории владельцев.** Каждый узел графа получает категорию — цвет в легенде «Владелец»:
кошелёк, биржа (CEX), биржа (DEX), фонд / маркет-мейкер, DeFi-протокол, эмитент, известная
персона, не атрибутировано. Источники: список известных адресов
(`api/src/constants/known-addresses.ts`), эмитент токена и его создатель, нулевой адрес
(минт и сжигание), а также проверки через Etherscan: смарт-контракты без известного владельца
и кошельки с 10 000+ транзакций попадают в «не атрибутировано» и, как биржи, не участвуют
в кластерах одного владельца. Проверяются самые активные и крупные адреса; остальные считаются
кошельками без проверки — в легенде видно, сколько кошельков проверено. Переключатель
«Поведение» возвращает раскраску по покупкам и продажам.

**Раскладка по группам.** В центре — исследуемый кошелёк (в графе токена — самый связанный
адрес), вокруг кольцами — его прямые контрагенты. Контрагенты со своими связями вынесены
в стороны, каждый со своим веером адресов; крупные группы ближе к центру. Острова — адреса,
переводившие только друг другу, — стоят на внешних кольцах; их можно скрыть в легенде.
Кнопка «ForceAtlas2» включает силовую раскладку,
«Группы» возвращает групповую (`graph/app/lib/graph-layout.ts`).

**Кластеры и поведение.** Адреса одного владельца объединяются эвристиками Union-Find
(пылевые рассылки, общий источник средств, взаимные переводы). Пороги сумм заданы в долларах
(`api/src/lib/thresholds.ts`): пыль — дешевле $2, общий источник — от $100. Цена токена
берётся с Binance (стейблкоины — $1, WETH/WBTC — по ETH/BTC); если пары нет, пороги
остаются в штуках токена, и интерфейс об этом сообщает. Независимо от этого K-means
делит адреса на поведенческие группы по 8 признакам (доля исходящих, размер переводов,
частота, число контрагентов, баланс и др.) и подписывает каждую: «в основном отправляет»,
«пылевые переводы» и т.п. Если все адреса кластера попали в одну группу, кластер получает
сигнал `kmeans_behavior` — поведение подтверждает общего владельца.

## Команды

В каждом проекте:

| Команда | Что делает |
|---|---|
| `npm run lint` | ESLint |
| `npm run typecheck` | проверка типов TypeScript |
| `npm test` | тесты Vitest |
| `npm run build` | production-сборка |

В API также `npm run start:prod` — запуск собранной версии из `dist/`.
CI (GitHub Actions) запускает lint, typecheck, тесты и сборку обоих проектов на каждый push.

## Windows

Нативный TensorFlow (`@tensorflow/tfjs-node`) на Windows не находит `tensorflow.dll` —
`scripts/fix-tfjs-node.js` после `npm install` копирует её на место. Если нативная библиотека
всё же не загрузится, API переключится на чистый JS (`@tensorflow/tfjs`): работать будет, но
обучение займёт минуты вместо секунд.
